# Feature-axis convolution mechanisms

O’Prior v1 §2.1 describes replacing fully connected layers with one-dimensional kernels along feature indices ([primary source](https://arxiv.org/html/2605.18971v1#S2.SS1), inventory `OP.function.07`). It does not supply complete channel-layout, padding, initializer or mixture laws. This core implements that operation with explicitly named r0 controls. It does not assert source-equivalent numeric settings or a full prior reproduction. Rows never enter the convolution axis; LimiX sample-axis convolution is a different scope.

`FrozenFeatureConv1D(input_length, input_channels, layers, layout)` retains actual shared kernels, not an expanded dense matrix or dense mask. Each `FeatureConv1DLayer` contains a `Conv1DGeometry`, a tuple kernel shaped `(output_channels, input_channels/groups, kernel_size)`, per-output-channel bias and activation settings. Inputs/outputs are float64 row-by-flattened-feature tensors. `channel-major` stores all positions of each channel together; `position-major` interleaves channels at each position. The layout is fixed and archived.

The deep-learning cross-correlation convention is explicit: output position p uses input `p*stride - left_padding + tap*dilation`; kernel taps are not reversed. `valid` adds no padding. `same-upper` outputs `ceil(length/stride)` positions, computes the minimum nonnegative total padding and puts the extra element on the right when odd. `explicit` uses the declared left/right zero padding; unused nonzero padding fields are rejected. Odd/even kernels and stride/dilation combinations share this formula. Grouped and depthwise kernels and post-activation identity residuals are r0 extensions. Residuals require equal input/output channel and position geometry.

Activation placement is either before convolution (on original inputs, then zero padding) or after affine convolution. `flat` applies the activation to the archived flattened order within each row; `channels` applies it across channels at each position; `positions` applies it across positions within each channel. This matters for softmax/rank and other coupled activations. A residual adds the unchanged incoming tensor after activation. Every affine and activation result must remain finite, even if a later sigmoid could conceal overflow. Evaluation is inference-only and does not build an autograd training graph.

`FeatureConv1DRequest` holds ordered `Conv1DLayerPrior` catalogs. Each layer independently selects a uniformly distributed geometry slot, activation slot and kernel-law slot from its declared finite tuples, retaining their exact indices. All supported catalog combinations must have valid grouped/position geometry. Initializers are standard Gaussian, uniform[-1,1), Student-t with declared df, standard Cauchy or Rademacher {-1,+1}. The kernel is `kernel_mean + kernel_scale * raw / sqrt(group_fan_in)` when fan-in scaling is enabled, otherwise the denominator is1. Bias has its own declared law/mean/scale and no fan-in scaling. These are reconstruction/extension laws; fan-in scaling is not a claim of unit variance, especially for uniform or heavy-tailed initializers. Zero scales and disconnected draws are retained rather than retried.

`sample_feature_conv1d(request, named_rng=..., raw_rng=...)` requires distinct owned NumPy bit generators. `SampledFeatureConv1D` retains the request, immutable function, choices, every raw kernel/bias/index draw and both initial/final stream snapshots with NumPy version/digests. Failure rolls both streams back. `validate_replay`, evaluation of a sampled record and `feature_conv1d_from_dict` reconstruct and compare complete type-exact custody. `feature_conv1d_request_from_dict` and the archive decoder require all declared fields, including nested records. Authored frozen functions remain separately usable without sampling claims.

`admit_feature_conv1d` and sampling preflight bound metadata, kernels, flattened widths, padded inputs, conservative im2col-sized backend workspace and raw/snapshot custody before allocations or RNG cloning. Caller limits remain authoritative on decode/evaluation. These are conservative estimated working bounds, not measured process RSS or an OS memory guarantee. No dense Toeplitz expansion is used.

The core and graph seams below implement shared functions, channel certificates, sampled custody and original-row traces. The guarded workbench below supplies explicit sampled graph catalogs. Complete internal innovation/importance combinations remain required follow-ons. Existing network/graph archives and sampler laws are unchanged. Hosted/GPU/scientific reproduction, performance measurements and a full suite are not claimed by this slice. Author evidence is ignored under `docs/evidence/issue-28-feature-convolution/`.
