# Recursive forests in causal graphs and native tasks

This slice integrates the independently reviewed [MITRA recursive core](issue-28-mitra-recursive-forests.md) as a structural mechanism. It preserves the source's unresolved class-start and lifecycle distinctions. It introduces no new source hyperparameter distribution and does not reproduce the whole MITRA prior.

`FrozenRecursiveForestFunction(source)` accepts either an authored `RecursiveForest` or the complete `SampledRecursiveForest` construction receipt with lifecycle `frozen-function`. Its versioned nested archive retains the plan, every raw draw, reconstructed forest, generator implementation/state/digests and construction limits. Graph JSON and task archives carry that envelope without extracting the forest and discarding its receipt. Reopening validates every retained sampled field before use. Old function and recipe records remain unchanged.

For regression, output channels are coordinatewise means of the reached tree leaves. For classification, outputs are **majority-label indicators**: precisely one channel is1 and the rest0 after the source's declared tie policy. They are neither averaged class probabilities nor stochastic softmax logits. `recursive_forest_native_node(function, parents=..., root=..., vocabulary=...)` uses deterministic argmax on those indicators to emit the exact class label, with no additional structural noise, preprocessing or target adapter. Native task targets remain int64 with the declared vocabulary. Descendants receive the existing explicit one-hot encoded state. Generic authored transforms of these indicators are possible, but constitute additional mechanisms rather than source majority-label emission.

All core controls remain available: source prose/Algorithm4/r0 branches, depth and stopping controls, estimator count, intervals and weighted feature extensions, vector Gaussian leaves, cyclic/IID labels and all three tie policies. Shared graphs support root or internal forests, parent composition, native scalar/vector and typed-converter equations. Frozen forest parameters stay fixed when task identity, query count or split changes. The actual row traversal is float64 with equality left; it does not adopt fitted-tree float32 casting. Literal path evaluation runs on CPU and returns values on the requested tensor device; GPU-native acceleration is not claimed.

Population certificates are bounded **conditional on retained finite leaves**. They retain conservative ancestry of every internal split feature. They make no unconditional claim over repeated forest constructions and infer no independence from a finite query sample. Graph metadata identifies this scope and distinguishes authored forests from sampled raw-custody envelopes.

Admission includes complete records, nested sampled reconstruction budgets, path and indicator buffers, parent composites and caller geometry. Public JSON admission reserves all nested replay budgets before any construction RNG restoration, including class-indicator width. Graph execution admits aggregate records and replay work before tensor/root allocation. Bounds are conservative estimates, not process-RSS measurements.

Inspection shows original-row paths, each reached regression leaf or actual class label, the mean/vote reduction and downstream equation links. Repeated/out-of-order requested rows retain their original positions. Matched hard interventions retain the frozen construction; categorical clamps bypass the original equation. Function-stage interventions retain the original graph and display the effective replacement forest's paths. Save/reopen and replay use the same typed task/archive contracts and exact integer identities.

`fresh-forest-per-row` is explicitly rejected by the frozen structural wrapper. Its independently reviewed core remains available with an exact original population row count, but a distinct population task/graph envelope and matched intervention ownership are still REQUIRED follow-ons. It is never silently converted to a frozen function. Graph request catalog sampling, population-reference workflow, workbench/shared-notebook controls, broader paper-law reproduction and scientific/resource/GPU evidence remain required separate work. This core graph/task slice does not claim them complete.

Author checks and preserved RED logs are ignored under `docs/evidence/issue-28-recursive-forest-graphs/`. Independent exact-head acceptance and combined release verification remain separate.

The whole-task JSON preflight also reserves declared row populations, root/parent widths, native encoded states and emission buffers, converted post-functions, calibration row floors and nested root replay before restoring a sampled forest RNG. It uses retained authored forest geometry only for this array-free reservation; it does not replace or alter the original sampled receipt, which still undergoes complete strict reconstruction afterward. Conservative aggregate reservations can reject a task whose individual forest would fit alone.
