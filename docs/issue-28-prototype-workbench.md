# Prototype root workbench: independent frozen banks

The shared explorer exposes 63 prototype presets: seven architecture templates, three explicit weight laws, and ceil/floor/nearest-even count conventions. `prototype-root-network` wraps a standalone architecture or source-profile root construction. Controls declare reference rows, rho, maximum count, trials, beta, probabilities and a separate exact bank seed. Complete JSON retains raw caps and nested source profile/independent normalization settings. The guarded generation worker constructs and replays the bank before publishing a dataset.

P2 motivates shared prototypes and convex weights, but does not uniquely specify integer counts or a beta-to-trials mapping. The UI labels those mappings as r0 reconstructions; probability-temperature and Dirichlet variants are extensions. Each generated row uses one weight vector across the whole bank. Prototype base normalization, if selected, uses an independent population before bank construction; it is not normalization fitted to the displayed query rows or to prototype outputs.

Frozen Next/replay retain bank values, weight law and all source/normalization/initial/final/raw construction records. Construction details show the complete bank and provenance. Architecture edits retain it. The root editor defaults to read-only retention; an explicit authored-copy policy permits editing bank values and weights while removing sampled-bank claims from the new draft. The original archive remains unchanged. Invalid text stays editable and cannot replace the accepted diagram. Generation, trace replay, root editing, source-noise composition and response grids use existing guarded workers and caller limits.

Save, reopen, ZIP export and the local notebook callback use the shared paths. Actual Chromium verifies all three weight laws, exact large identities, frozen Next/replay, malformed-edit retention, authored bank edits, saved-edit reopening/export, repeated original-row traces and timeout preservation. Hosted Colab and GPU execution are not claimed.

The separate [batch-reference workbench](issue-28-prototype-batch-workbench.md) now reconstructs an explicit population per task identity. It never silently converts a batch-dependent bank to an independent one. Prototype-output normalization profiles and sampled prototype-parameter profiles also remain separate required breadth.
