# Typed and retained-envelope intervention policies

This extends the sampled policy library, not TAFFY's claimed source law. The
[TAFFY Appendix A.3](https://arxiv.org/html/2610.07559v1#A1.SS3) selection/bounds
contract remains in the separate scalar functional profile. The new
`explicit-typed-policy-r0-v1` profile is explicitly an r0 extension.

`TypedInterventionPolicyRequest` retains the complete original graph or sampled /
fixed-fitted envelope. `InterventionPolicyLocation` names a numerical channel set
and state/readout/both location, a native logical variable, or a converter capture
and capture-only/representation-and-capture location. One sampled non-label
address set applies per selected node. A node with several eligible addresses
counts once; explicit eligibility/count or fractional node count is retained.
Hard addresses may select a sibling variable/capture in a joint label node, but
cannot clamp the declared target itself. Soft joint-equation replacement cannot
select a label node. This is not the scalar source node-count convention.

Categorical choices use the complete declared vocabulary, uniformly or with an
explicit ordered probability vector. They do not use domain frequency offsets
as claimed marginal probabilities. A sampled category is constant for the
intervention environment. Native variables retain encoded parent states and
truthful forced scores/probabilities. Converter capture-only clamps preserve
original descendant representation and its original emission-uniform dependency;
representation clamps preserve later structural noise and importance. Original-
input converter modes retain their explicit inverse-representation refusal.

Continuous clamps use finite complete reference-population extrema and one
quantile per addressed channel. Independent calibration uses a separate keyed
namespace; source-reference mode uses the original family's keyed population
protocol and complete declared row count. Every reference root, structural
innovation and typed emission draw is retained. Categorical-only policies need no
reference draws and their card marks bounds unused. Soft policies retain the
existing four explicit numerical parameter laws, function class and geometry,
parents, domains, converters, unlisted parameters and noise laws; no backend
refitting or architecture/hyperparameter prior is inferred.

The runtime view is used for geometry/evaluation only. Original sampled raw
records, calibration, fits, backend provenance and graph envelopes remain in the
request and intervention base and are strictly replay-validated before execution.
Authored native, native-vector and converted graphs, their sampled envelopes, and
fixed ancestor-fitted functional graphs have focused public checks. Other already
registered frozen functional envelopes use the same retained dispatch, with no
claim of exhaustive combinations. Population/support-refitted lifecycles refuse
explicitly and remain required follow-ons; their fitting population must not be
silently substituted with a frozen equation view.

Admission uses one metadata-only planner for both live sampling and strict decode.
It intersects nested runtime and outer caps and charges three graph views (complete
reference, original comparison and effective comparison), pair buffers, full original
request storage, complete-reference raw draws and initial/final snapshots. The graph
planner reads retained authored function geometry without replaying sampled kernels
or forests; full construction replay costs and sampled/prototype root custody remain
charged. Original sampled-envelope calibration rows and fixed ancestor-fit rows are
included, with native model replay costs for fixed XGBoost fits. Authored previews
never replace the request's retained original envelopes or alter their declared caps.
Every eligible address is admitted before selection. These conservative estimates
may reject tighter budgets than a specialized planner; they do not reduce counts,
widen caps or retry. Native-vector declared-cap requirements remain in force.
Typed receipts have a new version; scalar v1 policy archives remain unchanged.

Task generation, exact recipe decode, before/after comparison and pair persistence,
semantic metadata verification and repeated-row inspection are library seams.
The local explorer and shared callback now route typed policy drafts through the
bounded pair worker. `typed_intervention_policy_request_from_dict` performs full
metadata admission and complete outer request semantics before replaying the retained
original envelope. A validation-only authored graph uses retained source laws,
calibration, prototype banks, equation geometry, domains and converters. It never
replaces the stored base; soft parameter paths are checked against the original
full function metadata, including sampled convolution custody. The runtime
constructor and this preflight share the same semantic validator. The typed
profile exposes native logical variables, numerical state/readout locations,
converter captures, declared category probabilities, all four parameter laws,
reference lifecycles, population coupling and exact decimal stream identities.
Editable JSON retains the broader eligibility/count/fraction and multi-address
options. Existing authored/sampled native, vector, converter, parent-composition,
fixed fitted-tree and XGBoost construction catalogs remain selectable as originals.
TAFFY controls retain their narrower source restrictions.

Policy creation preserves the active original and any previous comparison on
invalid requests or worker timeout. Original-row comparison traces, including
construction draws with global scope, support repeated row indices. Saved pair
reopening and ZIP export retain both complete recipes. Opening the policy result
as active supports frozen Next, replay, ordinary task ZIP export and guarded
inspection; it does not resample policy values. To edit policy settings, reopen
the original before.zip and save another comparison. Direct mechanism editing of
a realized policy envelope and intervention-aware reference curves remain explicit
required follow-ons; those controls are unavailable rather than stripping policy
custody. Hosted Colab, full-suite and complete #28 acceptance are not claimed.
