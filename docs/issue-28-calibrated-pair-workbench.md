# Retained calibrated comparison archives in the explorer

Opening a calibrated comparison's `after.zip` displays the current task's saved
rows, context, feature count and target type. This wrapper stays a retained
comparison: its original query, changed population, comparison identity and
independent fit remain intact.

Next is explicitly unavailable for this archive. The interface explains that this
operation remains pending and directs users to reopen `before.zip` for fixed-fit
queries. Geometry editing and population construction drafts are not offered as
implicit transformations of the after-task. Query-capable calibrated populations
and ordinary tasks regain their normal controls when reopened/generated.

The population replay action, retained fit details, repeated original-row graph
inspection and export remain available. Backend query/refit/nested-edit actions
reject the retained comparison explicitly. No new query lineage or fitting rule
is introduced, and the saved source is never relabeled as an original population.

Validation uses matched/fresh public session tests and actual Chromium reopening
all four families, with fixed-fit archive comparison. The original independent
rejection is preserved separately. This repair does not claim calibrated response
curve integration, task-adapter comparisons, linked refitting, hosted execution,
or whole issue28 completion.
