# Explicit prototype batch-reference networks

`PrototypeBatchNetworkRecipe` is a reconstructible request containing a frozen standalone network source and explicit rho/count/weight/raw-budget controls. Its reference row count is always the task's row count; it cannot wrap an independently frozen `PrototypeRootBase`. The source can retain authored or sampled source-coordinate laws and independent construction-base normalization.

`realize_prototype_batch_network(request, seed, task_id)` constructs a separately versioned `RealizedPrototypeBatchNetworkRecipe`. It owns the complete `PrototypeBatchReference`, including prototypes, per-row integer counts or Gamma values, normalized weights, realized inputs and initial/final RNG snapshots. The two PCG64 streams are keyed by the named batch-population protocol, exact seed, task identifier, row count and bank/weight role. The realization verifies that its initial states match that identity, its plan matches the request, and every retained draw replays. Population rows are ordinal 0 through n-1 before context/query splitting.

Generating a request constructs a new realized population. Generating a realized archive with the same seed/task identity replays its retained population. Changing seed or task identifier reconstructs from its original request; `with_task` with a changed row count returns a request so M is recalculated from rho*n. Changing only context size/split retains the population and source identity while changing episode identity. This is never implicit conversion to an independent frozen bank.

Generation evaluates the network on weights @ prototypes and applies the shared regression/classification target adapter. Original-row inspection shows retained counts/Gamma, normalization, shared bank multiplication, network blocks, scores and targets in dependency order. Repeated and nonsequential indices refer to original population rows. The trace verifies the saved arrays against replay first.

Noise/separation task pairs share the same realized bank and weight draws, inputs, scores and row split. Feature-extension and sparsity pairs are explicitly unsupported in this slice, remaining required breadth. They are not advertised as matched changes. Population reconstruction on different identities is a separate operation, not an assertion of common inputs or equal variance.

The runner binds request-to-realization output through strict decoding, canonical request comparison and inner/outer identity checks. A different valid request or seed cannot satisfy another request's output receipt. Saved groups retain realized archives and reopen without discarding their construction records.

Admission combines complete bank/weight raw budgets, standalone evaluation, retained records, row-weight matrices and reconstruction buffers before cloning population RNGs or allocating arrays. Strict versioned decoders reject missing required envelope and nested source fields; caller limits remain authoritative. Nonfinite/degenerate construction fails without retries or fallback.

This is a source-qualified r0 reconstruction of the underspecified P2 prototype scheme, using the explicit count/weight conventions in [the prototype core](issue-28-prototype-roots.md). It does not reproduce an undisclosed beta law. Dedicated [workbench controls](issue-28-prototype-batch-workbench.md) use the same request/realized distinction; batch internal neural innovations, prototype-output normalization and sampled prototype-parameter profiles remain required integrations. Existing frozen-bank records are unchanged. Author evidence is ignored under `docs/evidence/issue-28-prototype-batch-network/`; no full-suite or hosted/GPU claims are made here.
