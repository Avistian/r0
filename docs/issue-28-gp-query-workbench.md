# Fixed-fit GP query workbench

The GP calibration panel now offers explicit new query seed, task identity and
optional fixed locations. Construct creates a guarded `GPRootCalibrationQuery`;
Next uses the main seed, next exact task identity and the same location controls.
Both retain the entire current source and independent fixed fit. Replay retains
the active query exactly. Saved queries reopen with their task controls, complete
history, fixed-fit disclosure and separate current-query/fit graph selectors.

`construct_gp_root_calibration_query` and the `query-calibrated-gp-root`
GraphConstruction route validate the full future envelope before source replay.
Producer matching binds complete retained source, current request, exact identity,
CPU execution metadata and admitted lineage before canonical numerical custody.
Runs require one population. A failed construction leaves the active dataset
unchanged. Graph/task geometry controls remain unavailable on calibrated archives;
new task geometry starts from an explicit original construction.

All four graph families are supported for regression. Functional binary and
multiclass targets preserve their fixed calibration and stochastic adapter laws.
Direct native categorical targets retain the existing category-preserving
calibration boundary. Generic GP-root interventions, policies, reference curves
and task-only pairs remain visibly unavailable pending their own verified
retained-population workflows.

Author verification uses public constructor/session RED/GREEN tests, zero-work
malformed controls and producer custody cases, actual Chromium query/Next/replay/
reopen/export workflows, and literal downloaded GP/target calculations. Evidence
and fixture failures remain under ignored
`docs/evidence/issue-28-gp-query-workbench/`. No full suite or independent acceptance
is claimed here. The underlying core is separately frozen at b330144; inherited
fit disclosure and constant-channel trace labels retain their separate review
status.
